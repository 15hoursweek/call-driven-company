# user_todo/ — 本人にしかできない作業

- 置いてよいのは本人の手が要る作業だけ（認証情報の入力・二要素認証・CAPTCHA・本人性が要る同意や承認・本人しか持たない情報や意思決定）。判定の正本は `LOOP_DESIGN.md` の「user_todo の収録基準」。**推測で「AIには無理」と判定しない。無人で通らないだけのものは `ai_todo/` の `対話待ち` に置く**
- 本文の先頭に `引き渡し先: {本人が操作する画面のURL、またはアプリ名と到達手順}` を1行で書き、その画面を開いた状態にしてから引き渡す（ファイルを書いただけでは引き渡し未完了）
- 1ファイル = 1TODO。ファイル名は `{YYYYMMDD}_{状態}_{要点}.md`
- 日付は作成日で固定（状態が変わっても変えない）
- 状態は `PENDING` を基本とする（定義は `LOOP_DESIGN.md` ②）。変更はファイル名のリネームで行う
- 判断が下りた／作業が終わったらファイルを削除する（履歴は git に残る）。このディレクトリには常に未消化だけがある
- 打ち合わせの冒頭でチャットがこのディレクトリを一覧し、ファイルがあれば提示する。ファイル名だけで要点が分かるようにする
- 対話セッション（Claude Code）の冒頭では SessionStart フックが `ops/session-handoff.sh` でこのディレクトリを提示する。Claudeは最初の依頼に着手する前に引き渡し先を開いて本人に渡す
- 関連するAI側の続き作業があれば、本文末尾に `→ 関連: ai_todo/ の該当ファイル名` を書く

このREADMEはディレクトリを空にしないために置いている。運用の正本は `LOOP_DESIGN.md`。
