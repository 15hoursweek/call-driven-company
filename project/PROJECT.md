# claude.ai プロジェクト設定（雛形）

claude.ai に作成するプロジェクト（名前例: AI会社）の「詳細」と「手順」に設定する内容。`GITHUB_USERNAME` を自分のGitHubユーザー名に置き換えて使う。

打ち合わせはこのプロジェクトのチャットで行う。スキルを呼ばない雑談でも、正本の場所や保存ルールなどの前提が効くようにするための設定。

## 詳細（プロジェクトの説明欄）

個人で運営するAI会社の統括プロジェクト。打ち合わせと会社ドキュメントの作業をここで行う。正本はGitHubリポジトリ「GITHUB_USERNAME/docs」。

## 手順（プロジェクトの指示欄）

この会社（個人運営のAI会社）に関する正本の場所：
- 理念・根本ルール・事業一覧・フォルダ構成（保存先ルール含む）の正本はGitHubリポジトリ「GITHUB_USERNAME/docs」（mainブランチ）の COMPANY.md。GitHub MCPで読み書きする。会社レベルの判断や保存先に迷ったら、必ず先にこのファイルを読むこと
- 会社ドキュメントの正本は同リポジトリ配下。ローカルのPCは実行環境が必要な工程専用の作業場
- リポジトリのmdはGitHub MCPで直接作成・更新してよい（コミットメッセージは内容の一行要約。更新前に対象ファイルの現状を読む）。CodeCLIへのタスクは `ai_todo/` に `{YYYYMMDD}_未着手_{要点}.md` を新規作成して登録する（1ファイル1TODO。日付は作成日で固定）
- 事業やルールの詳細をこの手順に書き写さない。変更はCOMPANY.mdだけを更新する
- 打ち合わせ開始時に、リポジトリの `user_todo/` を一覧し、ファイルがあれば冒頭で提示すること（ファイル名だけで要点が分かる。本文が必要なときだけ読む）

音声モードの運用：音声モードではGitHub MCPの `get_file_contents` で既存ファイルの本文が読めないことがある（ディレクトリ一覧・新規作成・削除・リネームは正常）。よって音声モードでは既存ファイルの中身を変更せず、新規作成・削除・リネームだけで運用する。本文を読む必要が出たら、テキストモードへの切り替えを依頼するか、`list_commits`（path指定）→`get_commit`（full_patch）で新規作成コミットの全文を取る。
